# General rule checklist

These instructions adapt the 18 `anti-slop/*` rules. Rule names below omit that prefix. Apply each to the requested scope. Read the exceptions before suggesting a change.

## Preserve type information

- **`no-chained-type-assertions`**: Remove nested `as` or angle-bracket assertions that force incompatible types to agree. Chains consisting only of `as const` are exempt. Prefer inference, a correct contract, or runtime parsing; replacing two casts with one unsupported cast is not a fix.
- **`no-known-value-widening`**: Do not assign known values to explicit `unknown`, `object`, anonymous object contracts, or open dictionaries that discard available information. Check assignments, properties, return contracts, assertions, and local predicate calls. Prefer inference, a named domain contract, or `satisfies`. Empty dictionary accumulators and finite-key `Record` contracts are allowed. Do not widen a known value by passing it into a local `unknown` predicate; use predicates on unparsed boundary data. This policy also rejects some structurally sound anonymous annotations; describe those as policy findings rather than runtime bugs.
- **`no-widen-then-assert`**: Follow immutable local aliases. Remove flows that erase a known type through `unknown`, `any`, `object`, or a broad record and later assert a narrower type. Preserve the original typed value or redesign the actual boundary. Upstream detection does not establish arbitrary cross-file or mutable dataflow.
- **`no-object-parameters`**: Replace bare `object` inputs, unions containing them, and local aliases resolving to them with meaningful input contracts. This is not a ban on object-valued parameters, destructuring, or named interfaces.
- **`no-unknown-parameters`**: Application functions should take parsed domain inputs. Upstream exempts a parameter named exactly `cause` and the exact parameter narrowed by a type predicate, including assertion predicates. The exemption does not cover other parameters in that function. Keep genuinely untrusted data untrusted until parsed; do not relabel it as a domain type. If a required external signature needs `unknown`, report the policy conflict rather than inventing evidence.
- **`no-unknown-returns`**: Replace explicit return contracts resolving to `unknown`, `Promise<unknown>`, or `PromiseLike<unknown>` with parsed domain results or meaningful result unions. Follow local and transparent generic aliases. Removing the annotation while still returning unparsed data does not fulfill the policy's intent.
- **`no-unknown-type-aliases`**: Remove aliases that resolve to `unknown`, including scoped and transparent generic aliases. Replace them with an actual contract. A renamed alias does not establish a contract.
- **`no-unsafe-dictionary-type`**: Replace dictionary value contracts based on `unknown`, `any`, `object`, `{}`, or equivalent broad types with a meaningful value type. Inspect `Record`, index signatures, mapped types, and aliases. Constraints such as `T extends Record<string, unknown>` are allowed. Do not forbid all dictionaries, and do not invent a recursive JSON type unless the boundary actually guarantees JSON values.
- **`require-safety-comment-for-type-assertion`**: Remove unnecessary assertions first. For each remaining non-const assertion, add a nearby comment with a real invariant, using `// SAFETY: ...` or the repository's configured marker. Explain which check or contract establishes the claim. `as const` is exempt. A comment cannot make an invalid cast safe, and a safety comment does not exempt a chained cast from its separate rule.

## Parse boundaries and use typed operations

- **`no-runtime-typeof`**: Replace ad hoc runtime `typeof` narrowing with the existing boundary parser and typed domain operations. Type-position `typeof` is not a violation. Comparisons with the string `"undefined"` are allowed existence probes. Upstream defaults to rejecting other runtime uses, even inside guards; `allowInTypeGuards: true` permits them inside type-predicate and assertion functions. Honor that setting when present. In a schema-free repository, identify an explicit guard-policy choice instead of adding a dependency or substituting equally ad hoc checks to evade the rule.
- **`no-reflect-get`**: Replace global `Reflect.get` with typed property access, a properly constrained key, or boundary parsing. Preserve getters, proxies, and any explicit receiver semantics; direct access is not always equivalent. A locally shadowed `Reflect` is not automatically the global API.
- **`no-reflect-apply`**: Replace global `Reflect.apply` with a typed call. Preserve the function's `this` receiver and argument tuple; a method call or typed `.call` may be appropriate. Do not blindly detach a method or treat a custom `Reflect` binding as the global object.

## Avoid repeated copying and preserve behavior

- **`no-array-filter-map`**: Review adjacent eager array `filter().map()` and `map().filter()` passes. Use a single pass or lazy iterator helpers when runtime support and semantics permit. Lazy pipelines are allowed. Upstream recognizes local array evidence, not every custom method chain. Before rewriting, check callback execution order, side effects, exceptions, indexes, callback array arguments, `thisArg`, sparse arrays, and truthiness predicates. Fusing passes changes when callbacks execute. `flatMap` is an option, not a guaranteed performance win. TypeScript library declarations do not provide runtime iterator helpers.
- **`no-reduce-accumulator-copy`**: In inline `reduce` and `reduceRight` callbacks, inspect copies of the growing accumulator: `Object.assign({}, acc, ...)`, `Array.from(acc)`, `concat`, `slice`, `toSpliced`, `toSorted`, `toReversed`, and `with`, including immutable aliases. Prefer a loop or mutation of a fresh, privately owned accumulator. Verify that earlier accumulator versions do not escape and that the initial value is not shared input. Copying an individual input item is allowed; string concatenation is not an array copy. Named callbacks, nested helpers, reassigned aliases, and nested accumulator properties are outside the upstream rule's detection. Bounded copies are not automatically quadratic.
- **Companion `oxc/no-accumulating-spread`**: Check repeated array/object spreads that copy accumulated state in reducers and loops. Upstream recommends this native rule alongside its own copy rule. Apply the same ownership checks before replacing copies with mutation. Manual review does not prove that all quadratic work is absent.
- **`no-conditional-empty-object-spread`**: Remove object spreads whose conditional expression uses `{}` to omit fields. Preserve key presence, property precedence, evaluation order, and side effects. Prefer whole-object branches or conditional assignment to a typed optional property. Do not replace omission with `undefined`, falsy values, or a cast. Upstream intentionally supplies no automatic fix.

## Tests, names, and spacing

- **`no-module-mocking`**: Replace Jest/Vitest `mock`, `doMock`, and `unstable_mockModule` module replacement with real dependencies or a small explicit seam. Verify import bindings and scope before identifying a violation. This is not a ban on all spies or function fakes. Other runners may have analogous architectural issues, but label those as an adaptation rather than a guaranteed upstream match. Preserve test intent and repository-required mock isolation.
- **`no-shape-in-symbol-names`**: Rename locally owned symbols containing the case-insensitive substring `shape` to a domain name. This includes incidental substrings, not just a `Shape` suffix. Static external member access such as `schema.shape` is allowed. Do not rename a wire-format field or public API without accounting for its callers and compatibility.
- **`require-readable-spacing`**: Separate top-level declarations, multiline bindings, control flow, returns, and statements following blocks with readable blank lines. Keep compact runs of single-line bindings, imports, and overload signatures together. Attach documentation to its declaration; a leading comment starts a new binding group. Preserve existing blank lines and let the repository formatter own indentation and wrapping. If its formatter conflicts with this policy, report that conflict instead of repeatedly changing whitespace.
